PROJECT
Build the first production version of maissara.tech, the professional digital headquarters of Maissara Selim.

Do not treat this as a résumé website, generic portfolio, military-themed website, SaaS landing page, or AI-startup template.

The site should communicate one central idea:

Maissara works across operational practice, peace and security, institutional learning, strategic planning, research, and emerging technology — turning complex real-world problems into structured decisions, methods, tools, and capability.

==================================================
1. CORE DESIGN DIRECTION
==================================================

Design language:
“Operational Intelligence × Editorial Minimalism”

Reference qualities:
- Helsing: institutional authority and disciplined dark presentation
- Linear: spacing, hierarchy, restrained sophistication
- Palantir: systems/decision mentality
- Mapbox dark cartography: subdued geographical/topographic texture
- Observable: analytical information as visual material
- Vercel: implementation quality and restrained motion

Do NOT clone any reference.

Avoid:
- camouflage
- weapons
- crosshairs
- radar sweeps
- cyberpunk/neon
- fake classified interfaces
- excessive military terminology
- floating particles
- glassmorphism everywhere
- oversized rounded SaaS cards
- generic gradient blobs
- custom cursor
- excessive animation

The tactical/operational influence should be subtle and primarily visible through precision, typography, coordinates, fine grids, topographic structures, data relationships, and disciplined information architecture.

Desktop:
- 12-column grid
- max content width approximately 1280–1360px
- substantial section spacing
- restrained 1px rules and structural lines

Mobile:
- single-column

- significantly simplify background effects and animation
- no interaction should depend on hover

Corners:
- primarily square
- maximum approximately 6px radius
- tags may use compact rectangular treatments, not pill-heavy UI

==================================================
3. MOTION
==================================================

Motion should communicate structure, not decorate.

Use Motion for React only where useful.

Allowed examples:
- subtle section reveal
- thin rule extending into position
- project screenshot movement of only a few pixels
- slight image scale on hover
- very slow contour displacement
- progressive appearance of FIELD → EVIDENCE → ANALYSIS → DECISION → CAPABILITY

No constant visual noise.

Implement and test prefers-reduced-motion.

Avoid Three.js/WebGL in V1.
Use CSS and SVG for the analytical/topographic visual language.
